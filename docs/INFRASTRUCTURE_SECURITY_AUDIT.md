# Infrastructure security audit

Audit date: 2026-11-15. Source snapshot: [main 14286d5](https://github.com/ZAK1504/NASA_SPACE/tree/14286d5a69a92059a8b22761ee73fb4b20215510). All provider links below were consulted or identified for verification on this date. Findings are static-source observations, not deployed benchmarks. No cloud resources, billing, or application code were changed.

## Release blockers
1. Critical SSRF: processing.PreviewRequest.fits_url is caller-controlled; _find_or_fetch_fits_for_target calls FitsService.download_fits with requests.get and default redirects. Restrict to exact server-resolved archive products or strict HTTPS host/path allowlist; validate DNS and redirect destinations, prohibit private/loopback/link-local/metadata IPs, enforce egress controls. No exploitation attempted.
2. High: public discovery GET/POST/DELETE has no auth/ownership; JSON load/modify/write is non-transactional, catches parse errors as empty. Isolate existing records; migrate to browser-local with export/import or implement owned SQLite transactions and authorization. No public writes to shared file before gate. Review privacy; avoid committing notes.
3. High: wildcard CORS + credentials in config/main. Use exact allowed production origins, credentials only if needed; same-origin preferable. CORS is not authentication.
4. High: preview/stack/comparison inputs lack comprehensive upper bounds; public synchronous processing and spectral 8-thread preload allow CPU/disk exhaustion. Validate finite RA/Dec, FOV, product IDs, enumerated stretch/colormap, percentile ranges, query radius/count, tile order/channel/pixel bounds. Enforce byte/time limits, 1 heavy job, bounded queue, 429/503 with retry advice, duplicate request coalescing and rate limits per endpoint. Do not fake results.
5. High: unbounded PREVIEW_CACHE dict and disk cache; cache key omits URL/percentiles. Introduce bounded LRU and keys including actual product identity/settings/release. Size/TTL caps and disk reserve. Do not evict persistent user records.
6. Medium: downloader keys by basename and uses predictable .tmp, no concurrency lock, validates cache mostly by file size. Use normalized unique identifiers/hash, safe path containment, per-product lock, unique temp and atomic replacement, FITS validation, maximum decompressed bytes. Inspect HiPS path parameters for strict validation and path traversal.
7. Medium: health exposes filesystem location; exceptions expose internal details. Minimal public health, sanitized errors; disable or restrict /docs and /openapi.json if not intended for public. Keep useful provenance in scientific responses.
8. Medium: dependencies only minimum versions, no reproducible lock; perform pip-audit/npm audit in approved staging, pin tested versions, use nonroot runtime. No actual CVE scan performed.
## Deployment security
Caddy/Nginx TLS -> loopback Uvicorn, or named Cloudflare Tunnel with stable domain and no public origin port. Firewall 443 (and ACME validation if required), restrict SSH to admin source/key; no direct 8000 or database port. Disable password SSH, patch OS, least-privilege service user, read-only application tree, writable dedicated cache. Do not put secrets in VITE_ variables. GitHub private repo token/deploy key least privilege, no secrets in logs or committed .env. OCI metadata protection and outbound allowlisting. Limit log size/retention and redact journal/user data. Use Cloudflare edge controls if applicable but enforce origin limits regardless.
## Data/recovery
Back up private journal/SQLite using consistent snapshot/export, encrypted copy outside VM; restore test. Regenerable caches may be rebuilt; retain verified product manifest and selected demo assets. Use included volume backups within five total; do not assume reclamation preserves all state. Deploy versioned release directory, symlink rollback, service restart, frontend previous deployment. Single VM no HA. Keep static fallback status honest when API offline.
## Verification gates
Test disallowed URL/redirect and resource bounds without targeting real sensitive hosts; verify no cross-user journal read/write/delete; concurrent saves; rate and queue rejection; disk quota; TLS certificate renewal and expiration alert; no public 8000; CORS preflight; dependency checks; restore from backup; cold-cache scientific test. No public production deployment until all critical/high blockers resolved and reviewed.
